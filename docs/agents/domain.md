# Domain docs

This repository uses a single context. Before exploring an area of the codebase, read the root `GLOSSARY.md` and any relevant architecture decision records in `docs/adr/` that exist.

Use the glossary's terms in issue titles, proposals, and tests. Bring gaps in the vocabulary to domain modeling when they affect the work. If a proposal conflicts with an existing architecture decision, cite the decision and explain why it should be revisited.
